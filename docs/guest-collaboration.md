Create a **Named external guests** link from a file or folder. Choose Editor on a file or Contributor on a folder, invited emails, and an expiry. Write roles require current versions and a PIN sent to the invited email. A forwarded invitation creates no staff account, grant outside its root, or library/search access. Sharing onward is unavailable in this conservative first delivery; links cannot enable it.

A guest opens the shared page, requests their PIN, enters it, and opens **Versions and replacement**. They can replace a file, name a retained version, download it within the link's download permission, and restore it. Restoration creates a new attributed version while keeping earlier ones. In a reviewed folder it is a new submission: the approved pointer does not move. Folder contributors also upload files into their granted folder. This direct guest form accepts originals up to 8 MB; larger resumable guest uploads are not delivered here.

Organization sharing/security admins set re-verification (default 7 days, range 1–30) and maximum grant lifetime (default 30 days) on Links. A tightened policy applies on the next request. PINs have six digits, last 10 minutes, allow five guesses and are consumed once. Guest sessions are random, hash-stored, HttpOnly and link-scoped; archives exclude them. Existing email-confirmation links remain available for viewer/commenter links; writer emails offer PIN verification only. Verified-domain links retain their separate 12-hour session lifetime and their own grant expiry; the named-guest maximum does not age out a domain link. Revocation, expiry, current sharing policy, restricted descendants and download permissions apply to every guest action and original/range request. These authentication, expiry defaults await ct approval; no completed contract claim depends on that approval arriving later.

## Collabora Online

Chest includes its WOPI adapter and an official, digest-pinned CODE deployment at `services/collabora/compose.yaml`. CODE needs no Microsoft or Google account. Set the exact HTTPS Chest origin as `CHEST_ORIGIN` in your private deployment environment, then run `docker compose -f services/collabora/compose.yaml up -d`. Put its loopback port 9980 behind your HTTPS reverse proxy, forwarding WebSocket upgrades and retaining TLS validation. Set Chest's optional `COLLABORA_URL` binding to that HTTPS origin. Do not expose an unprotected editor or enable an administrative console with shared credentials. Keep the image current with security updates and review CODE's production concurrency/support terms for your installation.

From a writable Office file, choose **Open in Collabora Online**, then continue to the configured editor. Staff and guests use the same stable file WOPI address, enabling one shared editing session. Tokens are short-lived, file-scoped and stored as hashes, and are posted to the configured editor rather than placed in a Chest page URL. Every metadata read, original read, lock and save rechecks the underlying staff session or guest grant, PIN re-verification, expiry, content classification and quarantine. A revoked guest's open editor cannot save again.

Locks bind the current editing version and expire after 30 minutes. A changed lock or intervening version is refused instead of overwriting it. Refreshing an old lock cannot adopt a colleague’s restored version for stale editor bytes; reopening reads the current original. Automatic remote-restore delivery into an already-open editor remains a VERSION-001 gap. Successful changed saves are immutable versions attributed to the token's current verified identity; repeated identical saves add no invented version. Editing a governed file uses its latest submitted version and keeps the approved pointer unchanged. The adapter implements CheckFileInfo, GetFile, PutFile, Lock, RefreshLock, Unlock and GetLock; it does not expose rename, Save As, relative writes, grant management or a new file picker. Session and lock records are excluded from backups; erasure removes them with their file.
