# Agent adoption and limits

Chest uses one shared agent door at `/mcp`, with `/mcp/chest` as an alias. Open **Agents** to choose local policy, inspect decisions, pause agents, review work or decide exact pending approvals. A paired Business sends signed policy and stable people bindings; an email address alone grants no authority. Unanswered policy refuses effects.

The records clerk can inspect accessible originals and metadata, organize files, manage versions, propose and apply deterministic filing, review exposure, narrow grants, manage space membership, inspect storage and native device state, record version-review decisions, release quarantine under native authority, and prepare/send parallel signature envelopes. Every call uses the sponsor’s current native rights. Assignment grants no access; an agent cannot act as a human signer or claim a human confirmation.

## Declared registry

The live schemas and catalogue are generated at `/docs/agents` and returned by discovery. This implementation declares core tools, policy, Pause, audit and idempotency, plus the existing resources and specialist prompt. Seven resource templates describe sanitized native metadata. Events and subscriptions are undeclared: discovery omits them, `chest.events.list` is absent, and attempted calls return `capability_not_declared` without effects. Resource refresh, multi-sponsor journeys and new mail-event edges remain undeclared. Base 0.2.88 gates discovery and runtime against the same capability declaration. Native OAuth webhooks retain their separate connector purpose and uncertain-delivery controls.

The [generated agent catalogue](agents.md) lists every tool, scope, possible class, clause and schema from the declared registry.

## People, records and proof

Signed Business `owner_id` binds the native setup owner ID. Signed team IDs bind existing native operator IDs; no email-derived shadow accounts are created. Business owner is owner, a signed team admin is a Business editor, and a member is not a Business editor. A locally promoted native administrator gains no Business policy role. Native operator admission, organization domains, current role/grants, app allowlists, source pauses and MFA remain authoritative. Person doors and Undo use the actual verified native browser session, including its MFA proof. Existing OAuth credentials retain their original native MFA linkage. A Business agent that cannot satisfy a required native MFA/local-sign-in proof is inadmissible until a native proof bridge is declared. Unknown, inactive and excluded sponsors refuse authentication; matching an administrator email cannot repair an unknown subject. Credentials require the originating consent, and its revocation stops the next effect.

Resources: `chest://item/{id}`, `chest://item/{id}/version/{n}`, `chest://space/{id}`, `chest://request/{id}`, `chest://link/{id}`, `chest://device/{id}`, and `chest://approval/{id}`. The last is an exact-version native review, not a company policy approval. Visibility follows current native access; a restricted record and a missing record both return unavailable. Imported names and external/file text are untrusted. Catalogue metadata omits original text, credential values and bearer URLs.

Company approvals retain the exact server summary and native revision, and execute only after a real named person decides. Rename and filing plans expose native reversals under their current permission and stale-state guards. The conformance journey exercises a named reviewer reversing the exact rename through the review door; native filing Undo retains its additional native policy fences. The native audit records that reversal as the person with no agent actor. New versions and native activity name the agent and sponsor; mail preparation identifies the agent for the person.

## Capacity and unavailable work

Base protects this installation with 600 requests per minute and a 1 MiB MCP body. Direct original upload/read is limited to 512 KiB; immutable reads support Range and charge the full selected original against any explicit OAuth byte cap. Listing pages hold at most 100 items. These bound request rate and size, not business volume. OAuth grants expire after 24 hours. Their request/mutation/byte caps are optional and apply only if set when granting; pre-existing recorded caps remain in force.

No tool registers provider `cost`, and the journey declares `spend:{none:true}`. Paid Ask, model filing/classification and provider spend caps are unavailable through this door until Base supplies enforceable reservations. Uploading into an enabled native arrival-rule or standing model-filing scope refuses with `agent_arrival_continuation_unavailable` before admitting bytes: it cannot silently authorize a second effect at another destination. Existing human/native automation retains its original policy and is not claimed as adopted by this subset.

The target surface remains wider than this registry. Device queue repair executes in the companion; installation backup/restore requires its independent runner/CLI and a verified continuation binding. Agent signature application needs the native signer-consent lifecycle and completion bridge. Erasure prepare/run and permanent trash purge are undeclared. Search uses native filters and download-safe snippets; access reads show native item grants; request reads omit submissions; member changes cover space membership; settings cover sharing policy; duplicate apply merges a native pair without repointing outside references; sends cover parallel signature envelopes without automatic reminders. Full resumable originals, bulk edits, wipe, staff/admin lifecycle and all other security settings remain gaps.

## Retained decision custody

The door retains arguments, original results, pending approvals, review summaries, trace/audit and events. Once these stores or registered agents exist, native erasure records a visible installation-wide **agent decision custody** hold and retains selected originals and identities. The native pending-erasure publication atomically requires empty agent custody, and an additive SQL admission trigger prevents first agent capture while erasure is pending. A new registration that wins that race refuses erasure instead. This deliberately does not claim client-scoped erasure: retained-artifact mapping, permitted evidence redaction and a complete concurrent-capture fence remain a Base boundary. An owner must not treat a held result as erased. Native audit-identity anonymization made before first agent admission atomically prevents later agent identity capture for that native ID. After agent admission it also refuses with `agent_decision_custody_held` once any agent has been admitted, rather than leaving retained agent labels behind while claiming anonymization.

Portable and independent archives exclude `agent_door_*` and `bs_*` installation tables. Hosted restore clears them. Product history keeps agent attribution; the restored installation must pair and receive policy again. Old pending actions, decision capabilities and paired identity authority never transfer.

## Verification

Normal `rer verify` runs the production Worker, additive schema, signed native owner claim, real invited reviewers, the declared journey under autonomous and held policies, native rename Undo, policy/refusal/audit checks and read-only native witnesses. `tests/agent-door/network.mjs` is a test-only exact-origin content-scanner edge: it validates native payload size, SHA-256 and a per-run authentication value, then returns realistic clean/infected receipts. All native authorization, persistence, outbox, quarantine and audit paths run for real. Built-in mail edges supply captured invitation/envelope outcomes. No live provider credential is used.
