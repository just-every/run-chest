# Ask and scan reading

The owner saves a reader key in Settings, records the provider's verified data retention and residency terms, and approves the relevant data policy. Changing the saved reader requires fresh approval. Chest records those terms; it cannot change the provider's hosting region or retention practices.

Open **Ask** on an everyday file, folder or Library record. Enter a question and, optionally, a list of field names to extract. Choose whether retained versions belong in the question, approve an estimated USD budget, and approve sending the question and accessible passages. Each run needs fresh approval. The answer carries cited claims, with exact retained-version links and page numbers. The model selects authorized passage references; Chest attaches their verbatim source quotations. It refuses unknown references and field values absent from their quoted passages. Incomplete evidence and skipped readable files remain visible.

Original-text restrictions apply. Folder runs always show the same opaque notice about restricted entries, so neither their existence nor their names or counts are disclosed. Unreadable files, pending extraction and scope limits are named only when the requester can read the original. The service rechecks current access and provider authority before sending and before returning an answer. It exposes no model tools and never changes approvals, signatures, permissions or files.

Ask questions and answers stay in the current page; Chest does not persist them. Audit records retain the approved policy, exact version references and provider usage without the question, passages or answer. Provider receipts preserve the matching owner-entered quote. Missing usage, failed calls and unmatched prices remain unknown. There is no retry or alternate answer after a provider failure or an unverifiable citation.

The USD admission estimate uses a conservative UTF-8 input bound and the approved output-token ceiling at the matching provider quote. It is an estimate rather than a provider invoice or an account-level billing limit. Ask refuses work without a matching quote or when the reservation exceeds the approved amount. Reasoning tokens count toward the requested output allowance and provider accounting.

Automatic scan reading has a separate owner policy. It is off until explicitly approved. Every page transcription and each field-schema call reserves one call against a durable allowance shared by identical original bytes; failures and interrupted requests consume that allowance too. Changing policy, copying an original or asking to read it again does not reset spent calls. The owner also selects the maximum output tokens per call. These call and token allowances do not promise a USD ceiling; provider receipts show the available USD estimate separately.

The supported local scan-retention choice is explicit persistence until permanent erasure of the original. Age-based expiry is unavailable. Turning automatic reading off prevents new model requests while retaining the original, earlier searchable text, human-confirmed values and exact-version decisions. Ordinary erasure removes the reading copies and checksum allowance. Verified provider terms are bound to the selected provider configuration; the service makes no unverified provider-retention promise.

TIFF scans use bounded page decoding and the same OCR and confirmation flow as scanned PDFs. Common stripped grayscale, colour and fax-compressed TIFF pages are supported. BigTIFF, tiled pages, separate colour planes and unsupported encodings report their real refusal; no reading is invented.

The native iOS and Android panels and device journeys still depend on MOBILE-001 developer accounts, signing and distribution. The adopted privacy, consent, budget and retention policies await ct approval. AGENT-007 and SEARCH-002 remain partial.

Public-flow coverage is in `./tests/chest/ask-flow.mjs` (`askFlow`), `./tests/chest/ask-browser-flow.mjs` (`askBrowserFlow`), `./tests/chest/reading.mjs` and `./tests/chest/scan-fields.mjs`. The browser journeys run at 1440 and 390 with icon tooltips. `./tests/chest/ask-live.mjs` is an explicit provider journey with two Ask calls and five scan calls with synthetic documents and a per-run USD allowance; held credentials enter its environment without being written to source or output.
